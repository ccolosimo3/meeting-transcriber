        <h2>Less chrome, one clear place for each task</h2>
        <p>This is a design exploration, not a production update or a replacement approved specification. It reuses the previous proposal's synthetic meeting/workflow engine, with a presentation variant for comparing disclosure. All operations are simulated; no files, credentials, microphone, audio or provider are used.</p>
        <h3>What the other products teach us</h3>

        <p>The sources above are official documentation/promotional examples checked on 31 October 2026, not a hands-on trial of every app. Otter's cited article is dated May 2024. The general <a href="https://www.nngroup.com/articles/progressive-disclosure/">progressive disclosure principle</a> is to expose common actions first, label secondary groups clearly, and avoid deep layers of controls.</p>
        <h3>Opus 5.5 / high consultation</h3>
        <p>One fresh Claude Code context ran on Windows as <code>claude-opus-5-5</code>, effort <code>high</code>, through the authenticated subscription. It read the synthetic proposal and captures. It confirmed the heavy header/player and recommended a collapsible library, slim toolbar, compact transport, on-demand Find, and activity/warning visibility. Its web fetches were denied, so the product-source research here was independently checked by the lead. This is advisory input, not certification of this new study.</p>
        <p><strong>Lead adjustments:</strong> the raw saved-version dropdown lives in Details, with the selected non-default version pinned above the text. Jump remains a distinct action in Listening. Critical playback feedback wraps instead of being truncated. Added strings keep their supplied meaning and format; no new duration, participant count or recording date is invented. Opus also inspected the new study and captures: its feedback restored visible passage numbers, aligned filter chips with canonical speaker IDs, made filters individually removable, and gave unresolved-attempt review the primary emphasis. These changes were checked in the prototype, not certified as production behavior.</p>
        <h3>Recommended hierarchy</h3>
        <table><thead><tr><th>Group</th><th>Default</th><th>What opens</th></tr></thead><tbody>
          <tr><td>Library</td><td>Open on wide; one-pane navigation on narrow. Title search and one Show select.</td><td>Library button collapses/restores it. Folder menu holds full path, Choose and Refresh.</td></tr>

        <h3>Credible alternatives</h3>
        <p><strong>A · Collapsible library + document reader (recommended).</strong> Quick meeting switching, maximum reading space when needed, three clear secondary groups. <strong>B · Library home → full reader.</strong> Simpler on small windows, but more back-and-forth between meetings; use this on narrow windows. <strong>C · Permanent inspector.</strong> Immediate metadata visibility, but it consumes width and invites more panels than this personal app needs.</p>
        <p><strong>Collapse rules:</strong> hide presentation, preserve the meeting and playback. Never silently clear a filter, change a selected version, imply remote cleanup succeeded, or hide the only stop/cancel/recovery control. Disclosure state is session-only in this sketch. No resizable splitter, saved layout schema, new transcript grouping or automatic follow is proposed.</p>
        <p>Try Library, Find, Details, Listening, an active search with Find closed, a non-default saved version, and missing-audio/uncertain-upload states. The external State control still provides the previous proposal's synthetic future flow. Presentation interaction checks do not prove native media, persisted recovery or provider behavior. <a href="meeting-transcriber-gui-proposal.html">Previous reviewed workflow proposal</a> · <a href="meeting-transcriber-desktop-plan.html#next-priorities">Project delivery page</a>.</p>
