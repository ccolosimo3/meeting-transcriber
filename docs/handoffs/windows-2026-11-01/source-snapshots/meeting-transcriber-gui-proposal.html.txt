        <p><strong>One shared layout.</strong> A compact 280px library leaves one principal reading column. Title, Added date, exact status and saved-run count support scanning. <h2 id="design-brief-title">Proposal and next implementation boundary</h2>
<p><strong>MT-GUI-ORG-1 · Revision 2 · Layout proposal.</strong> Grounded in desktop source <code>1b3a64b</code>, the candidate in <a href="https://github.com/ccolosimo3/meeting-transcriber/pull/5">draft PR #5</a>. This deliverable is a layout proposal for personal Windows and Mac use. Production implementation is a separate next step after the user reviews the design. All meetings, playback and jobs above are synthetic, in-memory examples.</p>
<h3>Recommended organization</h3>
<p>Keep one compact library beside one flexible reading column. Put the meeting title and current status first; place saved versions and details nearby without making them compete with transcript reading. Keep playback available while reading. At narrow widths, a named Library control opens the list, selecting a meeting returns to the reader, and closing the list returns focus to its opener. Keep the existing product palette and native form controls. The theme toggle here is session-only.</p>
<p>A card dashboard would consume space without adding useful metadata. A permanent third inspector would narrow the transcript and mostly repeat the selected meeting. Both are rejected for this personal library. Extra folders, tags, favorites, participant counts, summaries and a transcript-wide search index are deferred: the current projection does not supply those fields, and none is needed to organize the existing reader.</p>
<h3>First production task: reader organization only</h3>
<p>The <strong>Reader slice only</strong> preview is the proposed independently useful first change. Reorganize the existing library, selected meeting header, saved versions, details, transcript controls and player; add derived status filters and responsive navigation. Omit New meeting, Record, Import, Transcribe, setup and job controls from that first production change. The completed reader remains useful even if creation work never ships.</p>
<p>Likely owners are <code>desktop/assets/index.html</code>, <code>app.css</code>, <code>app.js</code> and their user documentation. Reuse the existing four bridge actions and library projection. No schema, dependency, preference store, provider request, credential handling, file mutation or native capture is required. Preserve the current private-session, navigation, media-handle and shutdown owners. Internal composition is the implementer's choice within the observable behavior below.</p>
<ul>
<li><strong>Library truth:</strong> preserve the backend's bundle/run order. Display the supplied formatted value as <em>Added</em>, never as recorded date. Title search is a literal case-insensitive substring. Show filtered/total counts clearly. Choose-folder cancellation preserves the current library; choosing clears title search; refresh preserves it and retains a surviving meeting/run, with an explanation when selection disappears.</li>
<li><strong>Filters:</strong> All includes every row. Transcripts includes meetings with an eligible saved run, including saved-HTML fallback. Audio only means the exact <em>Recording saved</em> status. Needs attention includes cleanup-unconfirmed, unfinished, or incomplete/unavailable status. Groups may overlap. Historical status alone is not an error. Missing/ambiguous recording is a loaded-reader condition, not a library flag inferred before loading.</li>
<li><strong>Versions and recovery:</strong> show actual run labels and their status. Library status follows the default run; reader status follows the selected run. Keep remote-cleanup warnings visible without calling a usable transcript failed. Expose Open saved HTML for the selected run, including structured-text-unavailable fallback. Keep the full library path available in details. Long titles, paths and run labels must wrap without hiding actions.</li>
<li><strong>Reader behavior:</strong> preserve segment source order and ordinal identity, including duplicate IDs, equal/unsorted intervals, overlap, silence and zero-duration passages. Active playback uses each interval independently. Passage/timestamp activation seeks and plays; selecting text does not seek. Selecting a different meeting/run clears stale media, highlights, query, speaker, follow, scroll and speed. Late responses must not replace the current selection.</li>
<li><strong>Find and follow:</strong> literal passage-text find intersects canonical speaker identity, even when display names repeat. Count matching passages; previous/next and Enter/Shift+Enter wrap without moving focus. Filtering does not seek or pause. Follow starts off; manual navigation or filter changes release it. Jump to playing enables it and hidden playing passages get explicit feedback.</li>
<li><strong>Audio and keyboard:</strong> missing, ambiguous, changed, removed or unsupported audio preserves readable/searchable text and disables unavailable playback, seeking and follow. Explain timestamps beyond duration. Preserve native control semantics, selected-row state, named timestamp actions, visible focus, selection focus restoration and keyboard access at wide/narrow sizes in both themes.</li>
</ul>
<h3>Creation destination: future UX preview</h3>
<p>The full-workflow preview proposes New meeting → Record room or Import audio → Recording saved → an explicit Transcribe action that uploads to AssemblyAI → processing → usable transcript, possibly with a separate cleanup warning. Recording and saving should work offline without a provider key. This is a proposed destination, not a certified backend design or implementation authorization.</p>
<p>Before capture, Cancel discards only the unsaved draft. During capture, Stop &amp; save preserves audio; only validated audio becomes a completed recording. Permission, device and validation failures retain recoverable partials with an honest status. Import copies a source into a meeting folder; cancel preserves the source. The preview uses sample filenames and has no file picker or microphone access.</p>
<p>The upload boundary must be explicit before transcription starts. Missing-key setup here is explanation only, with no editable key field. Cancelling a job retains local audio and shows cancellation while it settles. An uncertain upload outcome must not offer a blind retry. A completed transcript with remote cleanup unconfirmed remains usable. Close choices must preserve active work or explicitly stop/save/cancel it, never silently discard it. These screens model user-facing intent; they do not establish that cancellation, background work or recovery is already implemented.</p>
<p><strong>Future scope stays available while browsing.</strong> Listening or choosing Done returns to the recording reader without changing the selected preview scope. New meeting remains available, and an eligible saved recording has a future-only Transcribe recording action that returns that same meeting and title to the explicit upload boundary. Reader slice only omits those actions and all future attempt indicators. Local validation must settle before meeting selection, New meeting or close can leave it; its retained audio remains unfinished until validation succeeds.</p>
<p><strong>Unresolved attempts stay with their recording.</strong> Unknown upload, cancelled transcription and failed transcription keep a separate future-only qualifier in the library and selected reader, including after visiting another meeting. The local base scan status stays unchanged. An unresolved attempt exposes a proposed review/support route and suppresses a new upload action; it is not cleared by listening, navigating or starting another meeting. The prototype models this only in memory. Production must project the existing receipt lifecycle through an authorized future boundary, reconcile the attempt and cleanup result before permitting another submission, and prove persistence/reload and cancellation at the real owner. No new receipt parser, store, provider operation or recovery implementation is selected here.</p>
<p>Separate backend tasks must establish shared import/run ownership, Windows private persistent writes, native-only key delivery, structured progress/cooperative cancellation and cross-platform capture. Reuse existing publication-before-cleanup and qualified cleanup validation rather than creating another lifecycle. The present reader bridge has no mutation operation.</p>
<h3>Grounding and verification</h3>
<p>Source at <code>1b3a64b</code>: <code>lib/meeting_library.py:160–167,203–218,258–298,341–359</code> owns ordering/status/runs/media classification; <code>lib/meeting_identity.py:13–43</code> derives the formatted Added value; <code>desktop/assets/app.js:119–200,212–274,289–540</code> owns current selection/find/timing/follow behavior; <code>desktop/main.py:29–90</code> exposes the four read actions. <p>Future seams: <code>bin/meeting-transcribe:115–151</code> owns copied import; <code>bin/record-meeting:155–214</code> is Mac capture with validation/promotion; <code>bin/transcribe-meeting:95–164</code> is Mac-coupled preflight/run orchestration. <code>lib/transcribe_assemblyai.py:440–581,628–709</code> publishes before cleanup and owns qualified recovery; it lacks a GUI job/cancellation interface. Its POSIX receipt writer at <code>83–108</code> needs Windows proof. Current native session ACL protection does not prove persistent meeting/key privacy.</p>
<p><strong>Proposal proof:</strong> render and interact with this actual standalone prototype at representative wide/narrow sizes in light/dark.         if(state.keyReady&&stage!=='key-missing')addAction(a,'Upload & transcribe',()=>futureState('uploading'),{primary:true});else addAction(a,'View transcription setup',setupPreview,{primary:true});
        addAction(a,'Listen to recording',()=>setReader(state.futureMeeting));addAction(a,'Done for now',()=>setReader(state.futureMeeting));
      } else if(['uploading','queued','processing'].includes(stage)) {
        const titles={uploading:'Uploading recording…',queued:'Waiting for transcription…',processing:'Transcribing your meeting…'};
        const c=card(inner,titles[stage],'Your local recording stays in the library. You can cancel this transcription without deleting it.');
        const job=make('div','job-status');job.append(make('span','state-icon','…'));const body=make('div');body.style.flex='1';body.append(make('strong','',stage==='uploading'?'Sending audio to AssemblyAI':stage==='queued'?'Queued with AssemblyAI':'Processing with AssemblyAI'));const progress=make('div','progress-line');progress.append(make('span'));body.append(progress);job.append(body);c.append(job);
        c.append(make('p','small muted','Cancellation and remote cleanup may need confirmation. No retry starts automatically.'));const a=actions(c);addAction(a,'Cancel transcription',()=>cancelJobDialog());
      } else if(stage==='cancelling') {
        const c=card(inner,'Cancelling transcription…','Your local recording is retained. Wait while cancellation and the remote cleanup outcome are checked. No new attempt will start automatically.');const job=make('div','job-status');job.append(make('span','state-icon','…'),make('strong','','Confirming cancellation'));c.append(job,make('p','small muted','Please keep this window open until this attempt settles.'));
      } else if(['cancelled','job-error','uncertain'].includes(stage)) {
        const content={cancelled:['Transcription cancelled.','Your local recording is safe. No transcript is ready from this attempt. Remote cleanup is unconfirmed.'], 'job-error':['Transcription stopped.','The job did not produce a usable saved transcript. Your local recording is kept; remote cleanup may need attention.'],uncertain:['Upload outcome unknown.','We cannot confirm whether the provider received this recording. Your local recording is safe. Check the existing attempt before submitting it again.']};
        const [title,text]=content[stage];const c=card(inner,title,text);c.append(make('p','notice','No automatic retry. Review the existing attempt and remote cleanup through the current support or cleanup route.'));
        const a=actions(c);addAction(a,'View local recording',()=>setReader(state.futureMeeting),{primary:true});addAction(a,'Review transcription attempt',()=>reviewAttempt(state.futureMeeting));
      } else if(stage==='complete'||stage==='cleanup-ready') {
        const cleanup=stage==='cleanup-ready';const c=card(inner,'Transcript ready.','The transcript is saved locally and ready to read. Your recording is still available.');
        const list=make('ul','check-list');for(const text of ['Local recording kept','Transcript saved','Saved HTML available'])list.append(make('li','',text));c.append(list);
        if(cleanup)c.append(make('p','notice','Remote cleanup is unconfirmed. The saved transcript is usable; review cleanup through the existing recovery or support route.'));
        const a=actions(c);addAction(a,'Open transcript',()=>setReader(state.futureMeeting),{primary:true});
      }
    }
