<h1>Open a meeting, find a passage, hear its audio.</h1>
<p class="callout"><strong>MT-DESKTOP-1 · Library and audio-linked viewer</strong><br>Specification revision 2 · 31 October 2026 · Inner and selected outer spec reviews approved. Implementation is the downstream action; this document does not itself grant execution or publication.</p>

<h2>Outcome and boundary</h2>
<p>A personal Windows and Mac desktop reader opens the existing local meeting library, shows recordings and saved transcript runs, and plays the corresponding audio when a passage is selected. It is independently useful alongside the existing Mac CLI: copying an entire meeting folder into the other computer’s library and refreshing restores the same text/audio relationship.</p>
<p>The operator selected Python, AssemblyAI, pywebview after a bounded desktop proof, simultaneous Windows/Mac GUI availability, and separate local libraries with manual folder copying. The latest request, “sounds good, continue driving this work,” follows the proposed implementation-ready specification. This phase completes the specification and its review gates. It does not create tracker issues, publish packages or start the later capture/provider work.</p>
<p><strong>Included:</strong> a packaged desktop entry point, explicit library selection and refresh, one row per bundle, available-run selection, read-only canonical rendering, local audio streaming, playback controls, in-meeting search, speaker filtering, existing saved HTML opening, and safe session/file access.</p>
<p><strong>Deferred:</strong> recording/import into the library, uploading or deleting provider data, live job controls, changing speaker names, transcript corrections, title/date edits, notes, global transcript search, persistent settings, a database, sync, accounts, automatic updates, codec conversion, FFmpeg packaging, and public signed/notarized installers. Existing commands and JSON/Markdown/HTML outputs keep their current behavior.</p>
<p>The whole deliverable is one reader boundary: filesystem projection → bounded bridge/media access → web reader → native packages. A storage service or generic desktop framework would add responsibilities without another current consumer.</p>

<h2>What the user sees</h2>
<h3>Library and saved runs</h3>
<ol>
<li>Launch into <code>~/Transcriptions</code> when it exists, otherwise an empty view with Choose library. A native folder picker changes the session’s root; Cancel preserves the previous view. The chosen root is explicit and displayed. Nothing is saved as a preference in this slice.</li>
<li>Recognize immediate child bundles that contain a candidate recording, partial recording, or <code>transcripts/</code> run directory. Ignore unrelated empty folders. Do not recurse outside the existing bundle/run layout. Show title, Added date when available, and a text status. Sort rows by descending bundle basename in UTF-8 byte order with a deterministic full-relative-name tie break; filter titles by literal case-insensitive substring.</li>
<li>One bundle is one meeting. List classified runs in the existing byte order and select the newest selectable run by default. An older usable run stays accessible. If the newest selectable run is historical but its JSON cannot load, show “Saved HTML available” and let the user open that export or select another run; do not silently call it a clean structured transcript.</li>
<li>State labels distinguish “Transcript ready,” “Transcript ready; remote cleanup unconfirmed,” “Historical transcript,” “Saved HTML available,” “Recording saved,” “Unfinished recording,” and “Transcript incomplete or unavailable.” Current or old receipt warnings are surfaced without exposing receipt content or offering a cleanup operation. No active-recording or active-job assertion is inferred from partial files.</li>
<li>Refresh discovers copied/newly published folders and external changes without touching them. Root/run disappearance or access denial gets a bounded explanation and Choose library/Refresh action; one malformed bundle does not hide others. An unreadable library is not presented as an empty library. Background scans cannot freeze playback or apply stale results after a root or selection change.</li>
</ol>
<p>After opening a meeting, show available runs, speaker labels/display names, text and an audio player. Before media metadata arrives, duration is unavailable; do not label the last transcript timestamp as recording duration. Source media can play even for recording-only meetings. No automatic playback on selection.</p>

<h3>Audio and text</h3>
<ul>
<li>Resolve media within the selected bundle using the existing recording-name rule. Exclude partial files. Exactly one regular candidate enables playback; zero candidates leaves readable text with “Audio missing”; multiple candidates show “Audio ambiguous.” Do not guess by extension or mtime, and do not modify or relocate files to repair them.</li>
<li>Native media controls provide play/pause and seeking; add back 10 seconds, speed choices 0.75×/1×/1.25×/1.5×/2× and a Follow control. Audio metadata owns the duration. An imported but unsupported codec, decode error or removed media disables playback with a clear explanation while retaining the transcript. No derived audio cache or conversion is introduced.</li>
<li>A timestamp/passage activation seeks to its segment’s start and starts playback following that user action when media is usable. Clamp to the known media duration; a segment starting beyond the recording remains readable but its seek action explains unavailable timing. Playback updates every interval containing currentTime, using start ≤ time &lt; end; silence has no active segment and overlapping intervals may both highlight. Zero-duration segments are readable and seekable but need no active-playback highlight.</li>
<li>Changing meeting, run or root pauses/detaches old media, clears old highlighting and prevents late callbacks from updating the new view. Refresh revalidates selection; removed or replaced media gets a new binding rather than continuing stale audio. View grouping may share speaker headings but must retain individual segment times and ordinal identity.</li>
<li>Follow begins off so reading is stable. Enabling it scrolls to the first currently active visible segment. User scrolling releases Follow; an explicit Jump to playing passage reenables it. Filtering can hide the active segment; then the player remains accurate and the reader does not pretend a visible passage is playing.</li>
<li>Find searches segment text with literal case-insensitive matching, shows matching-passage count, and offers previous/next with wrap. Speaker filtering uses canonical labels even when names duplicate. Combined filtering and zero matches remain clear; filters affect the text view only, not audio. Match styling uses escaped text nodes, never executable transcript markup.</li>
</ul>
<p>Use the existing two-pane concept and palette from <a href="meeting-transcriber-desktop-plan.html">the exploration concept</a>. A narrow window stacks library and reader without overlapping controls. Native keyboard operation, visible focus and named controls remain supported; do not create an expanded accessibility qualification program for this personal prototype. Light/dark themes are session-local and begin with the OS preference.</p>

<h2>Backend, media and session boundary</h2>
<p>Keep the implementation small: a Python desktop entry point, a library projection using existing parsers/classifier, a bounded bridge/media owner and local HTML/CSS/JavaScript assets. Proposed locations are <code>desktop/main.py</code>, <code>lib/meeting_library.py</code>, <code>desktop/assets/</code> and focused desktop tests/build configuration. An implementer may combine these where it reduces indirection without changing behavior.</p>
<p>Use session-scoped opaque IDs for discovered bundles/runs and invalidate them when the library changes. Do not send arbitrary renderer paths to Python. Expected caller shape:</p>
<pre>choose_library() → {cancelled, library, meetings, errors}
refresh_library() → {library, meetings, errors}
load_run(meeting_id, run_id_or_null) → {status, canonical?, media_url?, media_state, exports}
open_saved_html(meeting_id, run_id) → {opened, error?}</pre>
<p>These are bounded internal actions, not a public compatibility API. The native picker is the only way the page changes the filesystem root. Errors distinguish stale/unknown ID, access denied, malformed transcript and unavailable source. The desktop process removes any inherited ASSEMBLYAI_API_KEY before importing or initializing the native renderer, starting the local server or launching any child. This read-only slice does not retain the key and does not read credential files. Native renderer/media/opener children must never receive it. No generic file read, shell execution, API-key loading, provider adapter import or mutation action is exposed. Loading returns validated canonical text plus display metadata, not receipt bodies or whole audio bytes. For recording-only selection, run_id_or_null is null and returns meeting/media state without canonical data; a non-null unknown run ID is an error, never a fallback to another run.</p>
<p><strong>File authority:</strong> canonicalize the selected root once; every scan, load, stream and export-open operation must remain under it. Reject symlink/junction/reparse descendants at bundle, transcripts, run and artifact/media boundaries. Recheck at use, not just initial enumeration; a removed/replaced path must fail closed or bind a verified opened file handle, never follow an unchecked new target. The renderer cannot select a path by URL. Existing pure parsers remain owners; desktop containment adds Windows-specific checks without weakening the CLI classification contract.</p>
<p><strong>Media transport:</strong> use a single loopback-bound server on an ephemeral port with a per-session unguessable capability and backend-owned source handles. Static assets come only from the shipped asset directory. Media routes support GET/HEAD and valid ranges/206/416 without whole-file buffering. Reject unknown/expired bindings, raw/encoded traversal, other-file names and invalid Host/origin requests; no CORS wildcard or directory listing. Accept the same-origin media element’s legitimate request forms, including absent Origin where the native engine omits it. Responses carrying meeting content use no-store caching; tokens/content/paths are excluded from logs. Close the server and invalidate bindings on app exit. Built-in Bottle static range handling from the proof may be reused inside these access checks.</p>
<p><strong>Privileged document:</strong> only the packaged local app document can use the bridge. Transcript/name/title strings are data. Block unexpected same-window navigation, file-URL navigation, drag navigation, popups and downloads; saved HTML opens only after an explicit action, in the system browser without the bridge. No remote scripts/fonts/assets or embedded legacy HTML. Enforce a restrictive content policy and renderer settings with native navigation control where necessary; a post-navigation error page is too late to protect the bridge. If the pinned framework lacks a required public hook, a narrow native renderer adapter for navigation or browser-storage configuration is acceptable; do not fork the framework or silently drop the requirement.</p>
<p><strong>Session storage:</strong> run the webview in private mode, with browser profile/temp files under a task-owned per-user location whose permissions are established before launch. Windows directories/files must exclude broad user/sandbox groups using verified ACLs; Mac uses private ownership and permissions. A failure to establish the boundary prevents loading meeting content. Clean up only that session’s storage after shutdown; any leftover after interruption must remain private. Pinned Cocoa 6.2.1 uses WKWebsiteDataStore.defaultDataStore and ignores storage_path. Passing storage_path/private_mode alone is not sufficient evidence on Mac; the native adapter must establish the stated storage boundary before creating the content-bearing WKWebView, then verify actual storage locations/access. No transcript/audio copies, preferences or search index are persisted. This is narrow desktop-session protection; the shared transcript writer and provider credential store are separate later work.</p>
